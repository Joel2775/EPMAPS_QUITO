# ADR-008: Usar Expo Network para detectar la conectividad

## Estado
Aceptado.

## Fecha
27 de octubre del 2026

## Requisitos relacionados
R3, al consultar los datos de los medidores cuando existe conexión. R4, al permitir registrar lecturas sin conexión. R9, al mostrar el estado de conectividad y gestionar el envío automático de las lecturas pendientes.

## Contexto
La aplicación debe funcionar tanto con conexión a internet como sin ella. El técnico necesita consultar los datos de los medidores cuando hay conexión y continuar registrando lecturas cuando no la hay.

## Alternativas consideradas

| Alternativa | Ventajas en este proyecto | Desventajas en este proyecto |
| :--- | :--- | :--- |
| **Expo Network** | Permite consultar el estado de la conexión y detectar cambios en la conectividad. Se integra con el entorno Expo. | Indicar que existe conexión no garantiza que el sistema de la oficina esté disponible o responda correctamente. |
| **NetInfo** | Permite consultar el estado de la conexión y observar cambios en la conectividad. Ofrece información sobre el tipo de conexión y su disponibilidad. | Agrega una dependencia adicional y requiere verificar su compatibilidad con la configuración del proyecto. |

## Decisión
Se usa Expo Network para detectar el estado de la conexión del dispositivo y observar los cambios en la conectividad. Esta herramienta permite actualizar el indicador de conexión de la aplicación y ayudar a gestionar las consultas y el envío de las lecturas pendientes.

## Consecuencias
- Se agrega la dependencia de Expo Network al proyecto.
- Se debe consultar el estado de la conexión al iniciar la aplicación y detectar sus cambios.
- El indicador de conectividad debe actualizarse en las pantallas para informar al técnico sobre el estado de la conexión.
- Cuando se recupere la conexión, la aplicación debe permitir reanudar las consultas y el envío de las lecturas pendientes.

- Se agrega la dependencia de Expo Network al proyecto.
- Se debe consultar el estado de la conexión al iniciar la aplicación y detectar sus cambios.
- El indicador de conectividad debe actualizarse en las pantallas para informar al técnico sobre el estado de la conexión.
- Cuando se recupere la conexión, la aplicación debe permitir reanudar las consultas y el envío de las lecturas pendientes.
- La detección de conectividad no reemplaza el control de errores de las solicitudes al sistema de la oficina, ya que puede existir conexión a internet sin que el servidor esté disponible.

## Verificación
- Abrir la aplicación con conexión a internet y comprobar que indica que existe conectividad.
- Desactivar el Wi-Fi y los datos móviles y comprobar que el estado de conexión se actualiza.
- Registrar una lectura sin conexión y comprobar que se guarda localmente.
- Recuperar la conexión y comprobar que la aplicación detecta el cambio y puede iniciar el envío de las lecturas pendientes.
- Simular una conexión disponible con el servidor de la oficina inaccesible y comprobar que la aplicación gestiona el error sin perder los registros locales.

## Uso de IA
Se le pidió a la IA comparar Expo Network y NetInfo para detectar la conectividad en una aplicación móvil desarrollada con Expo. La IA recomendó Expo Network, coincidiendo con la decisión. También se consideró NetInfo, pero se prefirió Expo Network por su integración con el entorno Expo utilizado en el proyecto.
