# ADR-006: Usar Zod para validar los códigos y los datos del registro

## Estado
Aceptado.

## Fecha
27 de octubre del 2026

## Requisitos relacionados
R2, al validar el formato del código del medidor antes de realizar una consulta. R5, al validar los campos obligatorios según el estado del medidor. R6 y R7, al validar los datos de la lectura y las condiciones que hacen obligatoria la fotografía.

## Contexto
La aplicación necesita validar el código de cada medidor y los datos ingresados durante el registro de una lectura. El código debe tener el formato MED- seguido de seis dígitos numéricos. Además, los campos obligatorios dependen del estado del medidor y del consumo registrado.

## Alternativas consideradas

| Alternativa | Ventajas en este proyecto | Desventajas en este proyecto |
| :--- | :--- | :--- |
| **Zod** | Permite definir esquemas de validación y comprobar que los datos cumplan las reglas establecidas. Facilita validar cadenas, números y condiciones entre varios campos. | Agrega una dependencia y requiere definir los esquemas de validación correspondientes. |
| **Validaciones manuales con JavaScript** | Permiten comprobar los datos mediante condiciones y expresiones regulares sin instalar una librería adicional. | Las reglas pueden quedar repartidas entre diferentes pantallas y resultar más difíciles de mantener cuando aumentan las condiciones. |
| **Yup** | Permite definir esquemas para validar campos obligatorios, formatos y condiciones. Puede integrarse con React Hook Form. | Agrega una dependencia y requiere definir los esquemas. Para este proyecto, Zod ofrece una alternativa adecuada para organizar las validaciones y trabajar con TypeScript. |

## Decisión
Se usa Zod para definir y ejecutar las validaciones del código del medidor y de los datos del registro. Esta herramienta permite centralizar las reglas y comprobar que la información cumpla los requisitos antes de continuar con el proceso, reduciendo errores en los datos ingresados.

## Consecuencias
- Se agrega la dependencia de Zod al proyecto.
- Se debe definir un esquema para validar el formato del código del medidor.
- Se deben establecer reglas para los campos obligatorios y opcionales según el estado del medidor.
- Las validaciones deben aplicarse antes de guardar o enviar los datos del registro.

## Verificación
- Ingresar un código con el formato MED-123456 y comprobar que cumple la validación.
- Ingresar un código incompleto o con letras en lugar de dígitos y comprobar que se rechaza antes de consultar el sistema de la oficina.
- Seleccionar el estado normal y comprobar que la lectura sea obligatoria.
- Seleccionar el estado inaccesible y comprobar que se exija el motivo y no se permita registrar una lectura.
- Seleccionar el estado dañado y comprobar que se exija la descripción del daño.

## Uso de IA
Se le pidió a la IA comparar Zod con Yup y las validaciones manuales mediante JavaScript para una aplicación que utiliza React Hook Form y TypeScript. La IA recomendó Zod, coincidiendo con la decisión. Se descartaron las validaciones manuales como mecanismo principal porque pueden dispersar las reglas entre diferentes componentes.
