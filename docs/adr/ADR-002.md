# ADR-002: Usar Expo-sqlite para el almacenamiento local

## Estado
Aceptado.

## Fecha
27 de octubre del 2026

## Requisitos relacionados
R4 al momento de no tener conexión y se quedan como pendientes, R7 al momento de conservar la referencia en la uri de la foto, R9 al momento de tener la cola de pendientes y su conteo depende del guardado local, R10 al momento de validad el duplicado ya que se guarda el estado de envio.

## Contexto
La aplicación permite que el técnico registre lecturas de medidores de agua, incluso cuando no tiene conexión a internet. Para cumplir con los requisitos R4, R7, R9 y R10, se necesita un almacenamiento local que permita guardar las lecturas pendientes, conservar la referencia de las fotografías y controlar el estado de envío de cada registro. Expo SQLite permite almacenar esta información de manera estructurada y mantenerla disponible, aunque la aplicación se cierre. De esta manera, el técnico puede continuar trabajando sin conexión y recuperar sus registros cuando vuelva a tener señal.

## Alternativas consideradas
| Alternativa   | Ventajas en este proyecto   | Desventajas en este proyecto   |
| Expo SQLite   | Permite almacenar medidores, lecturas y borradores en tablas relacionadas. Utiliza SQL para consultar y modificar información. Permite realizar transacciones y establecer restricciones de integridad, como evitar registros duplicados. Es adecuada para trabajar sin conexión y recuperar los datos pendientes después de cerrar la aplicación.   | Requiere definir la estructura de las tablas. Se debe implementar manualmente la lógica de recuperación de borradores y sincronización. Agrega una dependencia al proyecto que debe instalarse y configurarse.   |
| AsyncStorage   | Es sencillo de utilizar y permite guardar información como la sesión del técnico, preferencias y datos pequeños. No requiere definir tablas ni escribir consultas SQL   | No es una base de datos relacional. Para guardar varias lecturas y consultarlas por medidor, fecha o estado, se tendría que organizar y procesar la información manualmente. No ofrece consultas SQL, relaciones ni restricciones de integridad propias de una base de datos. Se basa mediante estructura de clave: valor.   |
| React Native MMKV   | Ofrece operaciones de lectura y escritura rápidas. Puede ser útil para guardar configuraciones, estados pequeños y datos de acceso frecuente.   | No está diseñado para administrar registros relacionales. La consulta de lecturas pendientes, la validación de duplicados y la relación entre medidores y lecturas requieren lógica adicional. Agrega una dependencia nativa y su configuración debe ser compatible con el entorno Expo utilizado.   |

## Decisión
Se usa Expo SQLite ya que permite gestionar información estructurada mediante una base de datos relacional, permite conservar los datos ingresados durante un registro que ocupa varias pantallas, además ofrece consultar estructuradas y restricciones de integridad. 

## Consecuencias
Se agrega la dependencia de expo-sqlite al proyecto para así almacenar una base de datos local.
Se debe definir una estructura de tablas para almacenar los medidores consultados, las lecturas registradas y los borradores.
El conteo de lecturas pendientes se obtiene consultando los registros almacenados; la conexión y el envío automático deben implementarse aparte.
El esquema y las consultas de la base de datos deben mantenerse en el módulo de base de datos, no repartidos entre pantallas.
Aunque esta decisión se refiere al almacenamiento de lecturas, el proyecto también usa expo-sqlite/kv-store para persistir la sesión y el borrador del formulario.

## Verificación
Sin conexión, guardar una lectura y comprobar que permanece en la lista después de cerrar y volver a abrir la aplicación.
Comprobar que una lectura sin datos suficientes para compararla queda pendiente de verificación.
Guardar una lectura con foto y comprobar que el archivo sigue disponible tras reiniciar la aplicación.
Registrar un medidor en un mes y comprobar que un segundo registro del mismo medidor y mes es rechazado.
Comprobar que el conteo de lecturas pendientes coincide con los registros guardados.
Verificar que la lógica de sincronización puede consultar los pendientes y actualizar su estado al enviarlos.

## Uso de IA
Se le pidió a la IA comparar Expo SQLite con AsyncStorage para una aplicación de registro de varios medidores mediante formularios. La IA recomendó Expo SQLite, coincidiendo con la decisión. Debido a que permite almacenar información estructurada mediante tablas y consultas SQL, facilitando la persistencia de medidores, lecturas y borradores de captura. Se descartó AsyncStorage como mecanismo principal, porque su almacenamiento de tipo clave-valor no ofrece consultas relacionales.
