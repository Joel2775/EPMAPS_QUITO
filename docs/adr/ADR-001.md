# ADR-001: Usar Expo Router para la navegación

## Estado
Aceptado.

## Fecha
27 de octubre del 2026

## Requisitos relacionados
R8, en la parte que indica que el registro de una lectura ocupa varias pantallas.

## Contexto
La aplicación tiene una pantalla de inicio de sesión, una pantalla principal con la lista de lecturas y un registro de lectura dividido en varios pasos. El técnico debe poder volver atrás entre los pasos sin perder lo que ya ingresó. Además, según R8, si la aplicación se cierra a mitad del registro, al abrirla debe poder llevarse al técnico directamente al paso en que se quedó, sin que tenga que recorrer las pantallas anteriores. El proyecto se crea con la plantilla por defecto de Expo SDK 57.

## Alternativas consideradas
| Alternativa   | Ventajas en este proyecto   | Desventajas en este proyecto   |
| Expo Router   | Viene incluido en la plantilla de Expo, así que no agrega dependencias. Cada pantalla es un archivo dentro de la carpeta app, lo que hace visible la estructura de navegación. Permite navegar a una ruta concreta desde el código, lo que sirve para llevar al técnico al paso pendiente.   | Obliga a seguir una estructura de carpetas fija; cualquier archivo dentro de app se convierte en una ruta. Agrega una capa sobre React Navigation, que hay que conocer cuando algo falla.   |
| React Navigation configurado manualmente   | Control total sobre la configuración de cada navegador. Es la librería sobre la que se construye Expo Router, con documentación extensa.   | Hay que instalarla y configurarla a mano, lo que agrega dependencias y código de configuración que la plantilla ya resuelve. Las rutas se declaran en código y no se ven en la estructura de carpetas.   |
| Una sola pantalla que muestra los pasos con renderizado condicional   | No requiere ninguna librería de navegación para el registro de la lectura.   | El botón atrás del sistema en Android no retrocede entre pasos sin código adicional. La pantalla crece hasta mezclar la lógica de todos los pasos en un solo componente.   |

## Decisión
Se usa Expo Router, porque ya forma parte del proyecto generado y su navegación basada en archivos permite dirigir al técnico al paso pendiente con una sola instrucción.

## Consecuencias
No se agrega ninguna dependencia para la navegación.
Los componentes que no son pantallas deben guardarse fuera de la carpeta app, para que Expo Router no los convierta en rutas.
La navegación no conserva por sí misma los datos ingresados. Expo Router decide a qué pantalla se va, pero lo que el técnico escribió en cada paso tiene que guardarse en otro lugar. Esa decisión se registra en un ADR aparte.
Riesgo: si al abrir la aplicación se navega al paso pendiente antes de terminar de leer los datos guardados, la pantalla aparecerá vacía. La navegación a ese paso debe ocurrir solo después de cargar el registro pendiente.

## Verificación
La carpeta app contiene solo pantallas y layouts.
En el teléfono, el botón atrás de Android retrocede de un paso al anterior dentro del registro.
En package.json no aparecen paquetes de React Navigation instalados manualmente además de los que trae la plantilla.

## Uso de IA
Se le pidió a la IA comparar Expo Router con React Navigation para una aplicación de registro en varios pasos. La IA recomendó Expo Router, coincidiendo con la decisión. Se descartó su sugerencia de guardar el paso actual en los parámetros de la ruta, porque esos parámetros se pierden cuando la aplicación se cierra y no resuelven R8.
