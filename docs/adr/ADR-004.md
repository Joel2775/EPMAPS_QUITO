# ADR-004: Usar TanStack Query para consultar y almacenar en caché los datos.

## Estado
Aceptado.

## Fecha
27 de octubre del 2026

## Requisitos relacionados
R3, al consultar los datos del medidor y evitar descargarlos nuevamente durante la jornada. R4, al permitir que el técnico continúe registrando lecturas sin conexión.

## Contexto
La aplicación permite que el técnico consulte los datos de los medidores desde el sistema de la oficina. Para evitar realizar la misma consulta repetidamente, se necesita almacenar temporalmente los datos obtenidos y reutilizarlos cuando vuelva a consultar el mismo medidor. Además, la aplicación debe gestionar las consultas cuando no hay conexión a internet.

## Alternativas consideradas

| Alternativa | Ventajas en este proyecto | Desventajas en este proyecto |
| :--- | :--- | :--- |
| **TanStack Query** | Permite consultar los datos de los medidores, almacenarlos en caché y reutilizarlos durante un tiempo determinado. Facilita controlar los estados de carga, error y actualización de las consultas. | Agrega una dependencia y requiere configurar las claves de consulta y el tiempo de conservación de los datos en caché, con StaleTime y gcTime. |
| **Axios** | Permite realizar solicitudes HTTP al sistema de la oficina y controlar las respuestas desde el código de la aplicación. | Se debe implementar manualmente la caché, el control de errores y la actualización de los datos, lo que aumenta la cantidad de código. |
| **Fetch API** | Viene integrada en el entorno JavaScript y permite realizar solicitudes HTTP sin instalar una librería adicional. | No administra automáticamente una caché de consultas ni proporciona mecanismos específicos para controlar su actualización y reutilización. |

## Decisión
Se usa TanStack Query para gestionar las consultas al sistema de la oficina y almacenar en caché los datos obtenidos de los medidores. Esta alternativa facilita reutilizar la información consultada y controlar los estados de carga y error, evitando solicitudes innecesarias cuando el técnico vuelve a consultar un medidor.

## Consecuencias
- Se deben instalar dependencias de TanStack Query para poder administrar la cache.
- Se deben definir claves de consulta que permitan identificar los datos correspondientes a cada medidor.
- Se debe controlar qué sucede cuando una consulta falla por falta de conexión.

## Verificación
- Consultar un medidor con conexión y comprobar que se muestran sus datos.
- Volver a consultar el mismo medidor y comprobar que se reutilizan los datos almacenados en caché mientras sean válidos.
- Consultar un medidor diferente y comprobar que se obtiene la información correspondiente a ese medidor.
- Simular un error de conexión y comprobar que la aplicación informa del problema sin bloquear el registro local de lecturas.
- Comprobar que las lecturas guardadas en Expo SQLite permanecen disponibles independientemente de la caché de las consultas.

## Uso de IA
Se le pidió a la IA comparar TanStack Query con Axios y Fetch API para una aplicación móvil que consulta información de medidores de agua. La IA recomendó TanStack Query, coincidiendo con la decisión. Se descartó utilizar únicamente Axios o Fetch API porque, aunque permiten realizar solicitudes HTTP, requieren implementar manualmente la gestión de la caché y el control de las consultas.
