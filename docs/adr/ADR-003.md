# ADR-003: Usar Zustand con persistencia para guardar la sesión y el borrador del registro

## Estado
Aceptado.

## Fecha
27 de octubre del 2026

## Requisitos relacionados
R1, al momento de conservar la sesión del técnico hasta que cierre sesión. R8, al momento de recuperar el registro de una lectura que quedó pendiente cuando la aplicación se cerró o tubo alguna interrupción en el proceso.

## Contexto
La aplicación permite que el técnico inicie sesión mediante su código de empleado y una clave, y registre lecturas de medidores de agua mediante un formulario que puede ocupar varias pantallas. Para cumplir con R1 y R8, se necesita conservar tanto el estado de la sesión como los datos ingresados durante el registro de una lectura. Zustand permite administrar el estado compartido de la aplicación mediante un almacén, mientras que su middleware persist permite conservar ese estado utilizando un mecanismo de almacenamiento. Para la persistencia se utiliza expo-sqlite/kv-store, que permite guardar información mediante una estructura de clave-valor y es compatible con el entorno Expo utilizado en el proyecto.

## Alternativas consideradas

| Alternativa | Ventajas en este proyecto | Desventajas en este proyecto |
| :--- | :--- | :--- |
| **Zustand con persistencia** | Permite centralizar el estado de la sesión y del formulario de registro. Su middleware persist permite conservar los datos entre reinicios de la aplicación. Facilita compartir información entre las diferentes pantallas del formulario sin pasar propiedades manualmente. | Agrega una dependencia al proyecto. Se debe configurar el almacenamiento persistente y controlar la recuperación del estado antes de continuar con el registro. |
| **Context API de React con almacenamiento persistente** | Es un elemento de React y permite compartir el estado de la sesión y del formulario entre diferentes componentes. No requiere instalar una librería adicional para administrar el estado. | Requiere implementar manualmente la lógica de persistencia y recuperación de los datos. Cuando el estado cambia frecuentemente, puede provocar renderizados adicionales en los componentes que consumen el contexto. |
| **Redux Toolkit con persistencia** | Permite administrar el estado global de manera estructurada, facilita el seguimiento de los cambios y cuenta con herramientas para depurar el estado de la aplicación. | Agrega configuración y código adicional para una aplicación que necesita administrar principalmente la sesión y el borrador de un formulario. Su estructura puede resultar más compleja de lo necesario para este proyecto. |

## Decisión
Se usa Zustand con persistencia, porque permite administrar de manera centralizada la sesión del técnico y el borrador de lectura. Su middleware persist facilita conservar el estado entre los reinicios de la aplicación, mientras que expo-sqlite/kv-store proporciona el almacenamiento local necesario para cumplir con R1 y R8.

## Consecuencias
- Se agrega la dependencia de Zustand al proyecto para administrar el estado compartido de la aplicación.
- Se configura el middleware persist para conservar la sesión del técnico y el borrador del registro utilizando expo-sqlite/kv-store.
- Se debe definir un almacén para administrar la sesión del técnico y otro para gestionar los datos del formulario de registro.
