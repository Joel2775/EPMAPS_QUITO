# ADR-005: Usar React Hook Form para gestionar el formulario de registro

## Estado
Aceptado.

## Fecha
27 de octubre del 2026

## Requisitos relacionados
R5, al validar los campos obligatorios según el estado del medidor. R6, al validar la lectura y controlar la confirmación cuando el consumo es anómalo. R7, al comprobar si la fotografía es obligatoria. R8, al gestionar el registro mediante varias pantallas.

## Contexto
La aplicación permite que el técnico registre lecturas de medidores de agua mediante un formulario dividido en varios pasos. Según el estado del medidor, se deben solicitar diferentes campos y validar que la información esté completa antes de continuar. Además, algunas condiciones, como un consumo anómalo o un medidor dañado, requieren información adicional. Por ello, se necesita una herramienta que facilite administrar los campos y validar los datos ingresados.

## Alternativas consideradas

| Alternativa | Ventajas en este proyecto | Desventajas en este proyecto |
| :--- | :--- | :--- |
| **React Hook Form** | Permite administrar los campos del formulario, validar los datos y controlar los errores sin actualizar innecesariamente todos los componentes. Facilita gestionar formularios con campos obligatorios y opcionales. | Agrega una dependencia y requiere configurar las reglas de validación de cada campo. |
| **useState (Manejo manual)** | Es una herramienta integrada en React y permite controlar los valores de los campos sin instalar dependencias adicionales. | Se necesita administrar manualmente los valores, los errores y las validaciones, lo que puede aumentar el código cuando el formulario tiene varios pasos. |
| **Formik** | Permite administrar los valores del formulario, las validaciones y los mensajes de error. Ofrece una estructura organizada para formularios con varios campos. | Agrega una dependencia y puede requerir más configuración para administrar las validaciones y los campos de un formulario dividido en varias pantallas. |

## Decisión
Se usa React Hook Form para gestionar el formulario de registro de lecturas, porque facilita administrar los campos y validar la información según el estado del medidor. También permite controlar los errores antes de avanzar entre los pasos del formulario, reduciendo el riesgo de registrar información incompleta.

## Consecuencias
- Se agrega la dependencia de React Hook Form al proyecto.
- Se deben definir las reglas de validación para los campos obligatorios y opcionales.
- Los datos del formulario deben conservarse al avanzar y retroceder entre las pantallas.
- Si el medidor está normal, la lectura debe ser obligatoria; si está inaccesible, se debe exigir el motivo; y si está dañado, se debe exigir la descripción del daño.

## Verificación
- Comprobar que no se puede continuar si faltan los campos obligatorios.
- Seleccionar cada estado del medidor y verificar que se soliciten los campos correspondientes.
- Ingresar una lectura que genere un consumo anómalo y comprobar que se exijan la confirmación y la fotografía.
- Avanzar y retroceder entre las pantallas y comprobar que los datos ingresados se mantienen.

## Uso de IA
Se le pidió a la IA comparar React Hook Form con useState y Formik para gestionar un formulario de registro de lecturas dividido en varios pasos. La IA recomendó React Hook Form, coincidiendo con la decisión. Se descartó administrar todo el formulario mediante useState, porque sería necesario implementar manualmente el control de errores y las validaciones de cada campo.
